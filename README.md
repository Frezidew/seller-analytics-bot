# Аналитик магазина в Telegram

Продавец спрашивает: «Какие товары пора заказать по нашему регламенту?» Бот ищет правило пополнения в документах магазина, вычисляет продажи и запас по SKU, затем показывает вывод со ссылками на фрагмент документа и расчёт. Команда /sources раскрывает выдержку, SQL и результат. Текст ответа генерирует выбранная вами модель.

## Быстрый показ без аккаунтов

Из папки seller-rag, Python 3.11 или новее:

~~~powershell
python bot.py demo /cover
python bot.py ask "/find порог пополнения"
python bot.py check
~~~

В комплекте три учебных SKU, 35 полных дней и четыре документа. Первая команда показывает запас в днях, дни без остатка и покрытие периода. Вторая находит фрагменты с именем файла, разделом и номерами строк. На старте CLI учебный набор обновляется относительно текущей даты. Для рабочего магазина используйте отдельный источник.

## Подключить модель и Telegram

Выберите модель с поддержкой OpenAI-совместимых Chat Completions и JSON object. В PowerShell задайте переменные в том же окне, где запускаете бота:

~~~powershell
$env:LLM_BASE_URL = 'https://api.openai.com/v1'
$env:LLM_MODEL = '<имя модели у вашего провайдера>'
$env:LLM_API_KEY = '<ваш ключ>'
python bot.py chat
~~~

В консоли можно вести диалог, использовать /sources, /reset и /exit. Для Telegram создайте бота в @BotFather, затем укажите его токен и числовой ID владельца. Для нескольких пользователей одного магазина перечислите ID через запятую:

~~~powershell
$env:TELEGRAM_BOT_TOKEN = '<токен>'
$env:TELEGRAM_USER_IDS = '<числовой ID>'
python bot.py telegram
~~~

Откройте личку бота и нажмите «Старт». Один процесс обслуживает один магазин. Разрешённые пользователи видят одни и те же данные магазина. Четыре последние пары вопрос–ответ хранятся в памяти отдельно для каждого пользователя и очищаются после перезапуска. Свежие факты извлекаются заново при каждом свободном вопросе.

## Сценарий на три минуты

1. «Сравни выручку и рекламные расходы по каждому SKU за последние 7 полных дней и предыдущие 7. Где расходы выросли, а выручка упала?» Бот может выполнить сравнение по двум периодам в одном SQL-запросе.
2. «А какой у этих товаров запас в днях? Используй наш регламент пополнения». Для этого нужны и поисковый фрагмент, и цифры. Откройте /sources, чтобы показать клиенту методику и расчёт.
3. «Можно ли назвать доход после переменных расходов чистой прибылью? Чего не хватает?» Ответ можно сверить с методикой в finance.md.
4. «Сколько принесла конкретная рекламная кампания?» В учебной выгрузке нет атрибуции по кампаниям. Корректный результат — назвать недостающие данные.

## Данные магазина

**SQLite.** Задайте SELLER_DB как полный путь к базе с таблицей или представлением daily. Ключ строки — дата и SKU. Бот читает базу при запросе; сбор исходных событий из кабинетов WB/Ozon выполняется вашей выгрузкой. Для нескольких кабинетов заранее агрегируйте совместимые показатели либо подготовьте отдельные экземпляры бота.

| Обязательное поле | Значение |
| --- | --- |
| day, sku | Дата YYYY-MM-DD по Москве и артикул |
| sold, revenue_rub | Проданные единицы и выручка за день |
| purchased, purchase_rub | Полученные единицы и стоимость закупки |
| stock | Остаток на конец дня |
| updated_at | ISO 8601 с единым часовым поясом |

Дополнительно доступны orders, returns, ad_spend_rub, fees_rub, logistics_rub, cogs_rub. Денежные поля — целые рубли. Для корректной оценки покрытия нужна строка на каждый день и SKU, в том числе в дни без продаж. В запросах доступны только перечисленные поля. Возвраты, комиссии и метод признания выручки реального магазина опишите в его собственных документах.

**Google Таблица.** Подготовьте отдельный лист с этими же заголовками в первой строке. Включите Google Sheets API для проекта, выдайте сервисному аккаунту права читателя таблицы и настройте учётные данные. Снимку нужен отдельный путь в существующей папке.

~~~powershell
python -m pip install google-auth requests
$env:GOOGLE_APPLICATION_CREDENTIALS = 'C:\keys\seller-reader.json'
$env:SELLER_SHEET_ID = '<ID из адреса таблицы>'
$env:SELLER_SHEET_RANGE = 'daily!A:Z'
$env:SELLER_DB = 'C:\data\seller-sheet.sqlite3'
python sheets_sync.py
python bot.py check
~~~

Снимок обновляется перед запросами с интервалом 300 секунд. Интервал настраивается через SELLER_SHEET_MAX_AGE_SECONDS. Перед заменой снимка проверяются типы и уникальность ключа. При неудачном обновлении числовой источник считается недоступным. Для SKU с ведущими нулями используйте текстовый формат; updated_at — текстовая ISO-дата со смещением. Необязательные пустые ячейки остаются NULL. Валидатор текущего импорта принимает неотрицательные целые значения.

## Проверяемый поиск по документам

Задайте SELLER_DOCS_DIR как папку с UTF-8 файлами .md и .txt. При подключении своей БД учебные документы отключаются. Файлы разбиваются по заголовкам и строкам, совпадения ранжируются по BM25 с нормализацией русских окончаний. Изменения видны при следующем поиске. Для перефразированных вопросов можно включить семантический поиск. При заданном EMBEDDING_MODEL лексическая оценка объединяется с косинусной близостью векторов.

~~~powershell
$env:SELLER_DOCS_DIR = 'C:\data\seller-docs'
$env:EMBEDDING_MODEL = '<имя модели эмбеддингов>'
python knowledge.py index
python knowledge.py search "склад недосчитался коробок"
~~~

Поставщик эмбеддингов по умолчанию берётся из LLM_BASE_URL и LLM_API_KEY. Переопределения: EMBEDDING_BASE_URL и EMBEDDING_API_KEY. Кэш векторов хранится локально; путь задаёт SELLER_INDEX_PATH. При недоступности провайдера остаётся лексический поиск. Без эмбеддингов поиск также работает офлайн.

## Границы и проверка

Модель получает каталог разрешённых полей, примеры SKU, текущий вопрос и короткую историю. После обращения к инструменту она получает найденные выдержки или строки результата. При включении эмбеддингов провайдеру передаётся текст индексируемых фрагментов. Источник фактов для каждого ответа отмечен в сообщении. /sources показывает SQL и начало результата для проверки. Ссылка подтверждает, какой источник был использован; интерпретацию сложных расчётов стоит сверять с ним.

Для одного свободного вопроса разрешено до восьми обращений к чат-модели. SQLite открыт только для чтения; SQL ограничен по таблицам, функциям, времени и объёму результата. Проверка конфигурации и набор локальных тестов:

~~~powershell
python bot.py check
python knowledge.py status
python -m unittest discover -v
~~~

Тесты включают цепочку «документ → SQL → ответ», сравнение цифр независимым расчётом, обновление документов и снимка Sheets, ограничения SQL и разделение пользователей Telegram. Внешние API в тестах заменены заглушками. Для проверки конкретного провайдера запустите python bot.py chat с его ключом, задайте вопрос и откройте /sources.

## PostgreSQL

Для импорта агрегатов из отчётного представления установите `python -m pip install "psycopg[binary]"`. Задайте SELLER_PG_DSN для пользователя с правом чтения и SELLER_DB для нового локального файла. По умолчанию читается public.daily. Схему и представление можно выбрать через SELLER_PG_SCHEMA и SELLER_PG_VIEW. Запуск: `python postgres_sync.py`. Обязательные поля — day, sku, sold и updated_at. Дополнительные показатели импортируются по разрешённым именам. Снимок обновляется при повторном запуске.
